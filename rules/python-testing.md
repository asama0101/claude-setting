# Python のテスト規則

Python のテストを書くときに従う規則。pytest の公式ドキュメントの慣習を基準にする。

- 規則には **必須** と **推奨** がある。必須を外すときは、利用者に理由を示して了承を得る。
- 確認方法を〔機械〕（コマンド）か〔目視〕（レビュー）で示す。
- TDD は、グローバルの CLAUDE.md の原則4（成功基準を先に決める）に従う。完了前の検証の報告は、この文書の「4. 報告」に従う。

## 1. 道具と設定（必須）

- テストは pytest の関数形式で書き、`pytest` で実行する。
- 依存（`pytest` など）は `requirements-dev.txt` に `==` で固定する。
- pytest の設定は `pyproject.toml` の 1 か所に置く。
- 設定に `testpaths`・`xfail_strict = true` を書く。
- `addopts = ["--strict-markers", "-ra"]` も書く。
- 使うマーカーは `markers` に登録する。
- 配置・命名・フィクスチャ・`parametrize` は、pytest の公式の慣習に従う。
- 一時ファイルは `tmp_path`、環境の変更は `monkeypatch` を使う。
- 〔機械: 設定ファイルの確認。テストに `unittest.TestCase` がない〕

## 2. 見せかけのテストをしない（必須）

実装を壊しても落ちないテストは書かない。次は見せかけの例である。

- 2-1. assert のないテスト。
- 2-2. モックの戻り値や呼び出しだけを確かめるテスト。
- 2-3. 期待値をテスト対象のコードで組み立てるテスト。
- 2-4. 常に通る assert、弱い assert、広い `pytest.raises`。〔機械: `ruff` の `PT011`・`B017`〕
- 2-5. 正常系だけで、異常系と境界値がないテスト。
- 2-6. 実行順・現在時刻・他のテストのデータに依存するテスト。
- 2-7. `reason=` のない `skip`・`xfail`。〔機械: `pytest -ra` の出力〕
- 2-8. 一度も落ちるのを見ていない新しいテスト。〔目視: 赤の出力〕

特記のない項目は、目視で確認する。

## 3. 書き方

- 3-1. 外部（ネットワーク・時刻・乱数・環境変数・外部コマンド）だけを置き換える。自分のコードの内部は置き換えない。（必須）
- 機能ごとに、置き換えを使わない統合テストを 1 本以上持つ。〔目視〕
- 3-2. テストは単独でも任意の順でも通る。フレーキーなテストは、再実行で済ませず原因を直す。（必須）〔機械: `pytest path::test_name` で単独実行を確認〕
- 3-3. バグの修正では、再現テストを先に書き、赤の出力を残してから直す。（必須）〔目視〕

## 4. 報告（必須）

- 「テストが通った」と報告するときは、`pytest -ra` の出力を根拠に示す。
- 新しいテストには、2-8 の赤の出力も添える。
- Windows で文字化けするときは、`PYTHONUTF8=1` を付ける。
