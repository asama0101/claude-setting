# README の書き方の規則

README.md を書く、または変更するときに従う規則。GitHub の README の慣習（Make a README）に従い、慣習から外れる点だけを書く。

- 既存の README には、新規と変更した節から適用する。利用者が刷新を頼んだときだけ、全体を書き直す。
- 文章の書き方は `reference\writing.md` に従う。ここには重ねて書かない。

## 1. 読者

- 読者は、ツールを使う人にする。
- 内部構造、開発環境、テスト方法、設計判断は、README に書かない。
- 導入方法やコマンド表は、1 か所に書く。ほかの文書からはリンクにする。

## 2. 章構成

- 章は次の順に書く。該当しない章は省く。
  1. タイトルと 1 行説明（何のツールか、誰向けか）
  2. 機能
  3. 前提条件
  4. 導入方法
  5. 使い方
  6. 設定
  7. 困ったとき
  8. ライセンス
- 上の章に収まらない項目（更新、アンインストール）は、最も近い章の小見出し（###）に置く。
- 目次は書かない。GitHub が見出しから自動で出す。

## 3. 書き方

- 導入方法と使い方のコマンドは、コードブロックで書く。
- 書いたあと、手順どおり新しい環境で実行する。実行できないときは、報告に「未検証」と書く。
- 使い方に、最も基本的な例を 1 つ載せる。コマンドと期待される出力を書く。
- 前提条件に、OS と必要なソフトのバージョンを書く。
- 上書きや削除を伴う手順は、その手順の前に警告し、戻し方を書く。
- エラーは、画面に出る文言を見出しにし、原因と対処を書く。
- 表のセルは 1 文にする。長い補足は、表の下に書く。
- 項目の数、コマンド名、フラグは、コードと照合する。

## 4. 置き場所

- README は、リポジトリ直下に 1 つだけ置く。
- プラグインやパッケージのフォルダには置かない。ライセンスや出典の注記は、そのフォルダの `NOTICE` に書く。

## 5. チェックリスト

- [ ] 見出しが 2 の順番である（`grep '^#'` で確認）
- [ ] README がリポジトリ直下に 1 つだけある（`find` で確認）
- [ ] コマンド名とフラグが、コードにある（`grep` で確認）
- [ ] 手順を実行した、または「未検証」と報告した
- [ ] 上書き・削除の手順の前に、警告がある
