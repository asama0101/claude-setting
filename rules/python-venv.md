# Python の venv の規則

Python の仮想環境（venv）を作る・使うときに従う規則。1 は開発用の venv、2 はプラグインの専用 venv。

- 規則には **必須** と **推奨** がある。必須を外すときは、利用者に理由を示して了承を得る。
- 各規則の末尾に、確認方法を〔機械〕（コマンドで確認できる）か〔目視〕（レビューで見る）で示す。
- 2 は、`~\.claude\reference\plugin-rules.md` の A1・A4・A5・A6・A7・H5 の Python の部分である。言語を問わない部分は `plugin-rules.md` に残る。
- Python の書き方は `python-style.md`、テストは `python-testing.md` に従う。ここには重ねて書かない。

## 1. 開発用の venv

### 1-1. リポジトリ直下の `.venv/` に作る（必須。プラグインでない Python プロジェクト）

- **規則**: 開発用の venv は、リポジトリ直下の `.venv/` に作り（`python -m venv .venv`）、`.gitignore` に `.venv/` を入れる。venv はコミットしない。既存の別名（`venv/` など）は、`.gitignore` に入っていれば、そのまま使ってよい。
- プラグインの開発は、2-5 に従う。入口スクリプトは、リポジトリ直下の `.venv/` を探さない。
- **理由**: 依存をリポジトリごとに分け、システムの Python を汚さない。場所と名前をそろえると、探す手間と `.gitignore` の漏れがなくなる。〔機械: `git check-ignore .venv`〕

## 2. プラグインの専用 venv

用語（専用環境・置き場・入口スクリプト）は `plugin-rules.md` の「用語」に従う。

### 2-1. 専用 venv の中だけで実行する（必須。plugin-rules の A1）

- **規則**: 本体は専用 venv の中だけで実行する。システムの Python は入口スクリプトの起動にだけ使い、ライブラリは入れない・読まない。
- **理由**: 利用者のシステムに何が入っているかで動作が変わらないようにするため。システムの環境と専用 venv の「どちらかを選ぶ」分岐は、動作の再現を難しくするので作らない。〔目視〕

### 2-2. 依存は `requirements.txt` で `==` 固定する（必須。plugin-rules の A4）

- **規則**: 依存は `requirements.txt` で管理し、すべて `==` で版を固定する。固定する版は、新しい専用 venv で全テストが通った版にする。
- 専用 venv の版が `requirements.txt` とずれたら、入口スクリプトが検知して終了コード 3 で止める（2-4）。再同期は自動にせず、承認後の `setup --yes` で行う。
- **理由**: venv を作るたびに同じものが入り、動作を再現できるようにするため。〔機械: `requirements.txt` に `==` のない行がない〕

### 2-3. venv の導入は利用者の承認を得てから（必須。plugin-rules の A5）

- **規則**: 専用 venv の導入は、利用者に「どこに・何を・どのくらいの容量で入れるか」を説明して承認を得てから行う。承認なしには作らない。
- 動かなくなった venv（基底の Python が消えたものなど）を作り直すのは、承認済みの場所だけにする。
- **理由**: 利用者の環境を、承認なしに変えないため。〔目視〕

### 2-4. 入口スクリプトの契約（必須。plugin-rules の A6）

- **規則**: Python のプラグインの入口スクリプト（例: `run.py`）は、標準ライブラリだけで動かし、`plugin-rules.md` の A6 の `doctor`・`setup`・終了コード 0〜3 を持つ。
- 終了コード 3 の案内には、使っている Python のパスと専用 venv の置き場を含める。作成元の Python の最低版数と、`venv`・`ensurepip` が使えることは、プラグインごとに確認し、`doctor` と `setup` の案内に書く。足りないときも終了コード 3。
- **理由**: どのプラグインでも同じ振る舞いにすると、SKILL.md が「終了コード 3 のときは、利用者に確認して `setup --yes` を実行する」と書ける。〔機械: 環境がないときに終了コード 3 で止まることをテストする〕

### 2-5. 開発専用の探索を作らない（推奨。plugin-rules の A7）

- **規則**: 入口スクリプトに、リポジトリ直下の `.venv/` の自動検出のような、開発専用の探索を作らない。置き場は `<PLUGIN>_HOME`、`--data` の順で決める（A7）。開発では `<PLUGIN>_HOME` を指定する。1 の開発用 venv は、入口スクリプトからは使わない。
- **理由**: 開発もテストも、通常と同じ経路で実行できるようにするため。〔目視〕

### 2-6. 依存は PyPI から取得し、ハッシュを固定する（推奨。plugin-rules の H5）

- **規則**: 依存は PyPI から取得し、可能なら `--require-hashes` でハッシュも固定する。
- **理由**: 供給元の改ざんを防ぐため。〔目視〕
