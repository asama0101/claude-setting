# レビューの規則

`CLAUDE.md` の原則4のレビューの詳細。変更を完了報告する前、PR・マージの前に読む。

## レビュー
- ファイル数: 振る舞いに影響するファイル（コード・設定・エージェントへの指示（`CLAUDE.md`・`SKILL.md`・プロンプト））で数える。テスト・説明文書は含めない。同一目的の変更は、ターンを分けても合算する。
- 次の変更は、完了報告の前に、文脈を共有しない新規サブエージェント（fork 不可）にレビューさせる。
  - ファイル数が2以上の変更
  - 条件分岐・計算・データ変換を追加または変更する変更（CLAUDE.md の規則の意味を変える追加・変更を含む）
- 観点は「正しさと要件」「過剰実装とリスク」。ファイル数が2以上のときは観点ごとに別のサブエージェント、それ以外は1体に両観点。
- 依頼文に、対象の差分・要件・観点を明記する。
- 指摘は技術的に検証し、依頼の範囲内で観点に関わるものを直す。スタイルの好みは直さない。
- レビューを実行できないとき（サブエージェントを起動できない、または自身がサブエージェントとして実行中）は、理由を添えて「未レビュー」と報告する。
- 指摘の修正で、上のレビュー対象に当たる変更を足したときは、その部分を再レビューする。
- 再レビューは、同じ部分（同じファイルの同じ関数・節）につき2回までとする。PR・マージ前の全体レビューは、この回数に含めない。
- 2回の再レビューのあとに出た指摘は、直さずに、残る既知の穴として報告に書く。ただし、正しさ・安全に関わる指摘（データ破壊、規則の矛盾、認証情報の露出）は、止めて、AskUserQuestion で続行か受容かを確認する（使えないときは、作業を止めて報告する）。
- 範囲外または不採用の指摘は、直さず、理由を1行で報告する。
- PR・マージ前は、差分全体を要件と照らしてレビューする。主体は、PR 全体の差分が上のレビュー対象ならサブエージェント（観点と体数は上の規則に従う）、それ以外は自分で確認する。
