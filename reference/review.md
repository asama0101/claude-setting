# レビューの規則

レビューするときと、PR・マージの前に確認するときに読む。

## 15の観点

次の15項目を押さえると、レビュー漏れがほぼなくなる。

1. 目的適合性: 目的を満たしているか
2. 正確性: 誤りはないか
3. 完全性: 漏れはないか
4. 一貫性: 矛盾はないか
5. 品質: 十分な品質か
6. 効率性: 無駄はないか
7. 利便性: 使いやすいか
8. 保守性: 維持しやすいか
9. 拡張性: 将来に対応できるか
10. 安全性: リスクはないか
11. 法令・規則適合性
12. 費用対効果
13. 利害関係者満足度
14. 実現可能性
15. 改善余地

## 汎用レビュー・ループ v1

対象は何でもよい（文章・設計・コード・業務・提案書・事業計画）。

### Phase 1: 多面的検証（Cross Review）

異なる観点から対象を評価する。

- 観点の例: 目的・品質・リスク・実現性・効率・保守性・影響範囲
- 問い
  - 目的達成に十分か
  - 漏れはないか
  - 矛盾はないか
  - 無駄はないか
  - 将来問題にならないか

### Phase 2: 反証（Red Review）

「なぜ失敗するか」を考える。改善案を出すのではなく、成立しない理由を探す。

- 前提が間違っていないか
- 見落としはないか
- 想定外のケースはないか
- 悪用されたらどうなるか
- 最悪のケースは何か

### Phase 3: 改善（Improve）

指摘事項を統合し、Critical・High・Medium・Low に分類する。優先順位の順に修正する。

### Phase 4: 収束判定（Gate）

「重大な問題は残っているか」を確認する。次のどちらかを満たせば終了する。

- Critical = 0 かつ High = 0
- 品質スコアが95点以上
