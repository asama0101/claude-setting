# レビューの規則

レビューするときと、PR・マージの前に確認するときに読む。

## 15の観点

レビューでは、次の15の観点から確認する。

- 常に確認する観点: 1〜4と10（目的適合性・正確性・完全性・一貫性・安全性）。
- それ以外の観点: 対象に関係する成果物・利用者・規則・費用のいずれかがある観点を選んで確認する。外した観点は、レビュー結果に書く（書き方は「レビュー結果の出力」）。

1. 目的適合性: 目的を満たしているか
2. 正確性: 誤りはないか
3. 完全性: 漏れはないか
4. 一貫性: 矛盾はないか
5. 品質: 十分な品質か
6. 効率性: 無駄はないか
7. 利便性: 使いやすいか
8. 保守性: 維持しやすいか
9. 拡張性: 将来に対応できるか
10. 安全性: リスクはないか
11. 法令・規則適合性
12. 費用対効果
13. 利害関係者満足度
14. 実現可能性
15. 改善余地

## 汎用レビュー・ループ

対象は何でもよい（文章・設計・コード・業務・提案書・事業計画）。

### サブエージェント戦略

- Phase 1 と Phase 2 は、サブエージェントに行わせる。Phase 3 と Phase 4 は、自分で行う。
- Phase 1 は、観点を2つに分けて、2体のサブエージェントに割り振る（例: 正しさと要件／過剰実装とリスク）。Phase 2 は、さらに別の1体に行わせる。
- サブエージェントは新規にする（fork しない）。依頼文に、対象の差分・要件を書く。「問題はない」などの自分の結論は書かない。
  - Phase 1 は、担当する観点も書く。
  - Phase 2 は、観点の代わりに「成立しない理由を探す」と書く。Phase 1 の指摘は渡さない。
- サブエージェントとして依頼されたときは、依頼された範囲だけを行い、サブエージェントを起動しない。
- サブエージェントを起動できないときは、Phase 1 と Phase 2 を行わずに、理由を添えて「未レビュー」と依頼した人に報告する。

### Phase 1: 多面的検証（Cross Review）

異なる観点から対象を評価する。

- 観点の例: 目的・品質・リスク・実現性・効率・保守性・影響範囲
- 問い
  - 目的達成に十分か
  - 漏れはないか
  - 矛盾はないか
  - 無駄はないか
  - 将来問題にならないか

### Phase 2: 反証（Red Review）

「なぜ失敗するか」を考える。改善案を出すのではなく、成立しない理由を探す。

- 前提が間違っていないか
- 見落としはないか
- 想定外のケースはないか
- 悪用されたらどうなるか
- 最悪のケースは何か

### Phase 3: 改善（Improve）

指摘事項を統合し、Critical・High・Medium・Low に分類する。優先順位の順に修正する。

| 重要度 | 基準 |
|---|---|
| Critical | 目的を達成できない。データの破棄・漏えい、安全上の問題がある |
| High | 要件の漏れや誤りがある。既存の動作を壊す |
| Medium | 影響が限られる問題（既存の動作を壊さない。特定の条件でだけ起きる、保守しにくい） |
| Low | 好みや軽微な表記 |

複数に当てはまるときは、重い方を選ぶ。

### Phase 4: 収束判定（Gate）

「重大な問題は残っているか」を確認する。次をすべて満たせば終了する。

- Critical = 0 かつ High = 0
- 品質スコアを使うときは、95点以上である

品質スコアを使わないときは、1つ目だけで判定する。

満たさないときは、Phase 1 に戻る。ループは、同じ部分（同じファイルの同じ節など）につき3周までとする。3周しても満たさないときは、4周目に入らず、直さずに、残った指摘を「既知の穴」としてレビュー結果に書く。

品質スコアは、100点から、残った指摘ごとに減点して求める。Critical は30点、High は15点、Medium は5点を引く。Low は引かない。下限は0点。

## レビュー結果の出力

レビューをした人が出す結果は、次の形にする。

- 指摘は、重要度の順（Critical・High・Medium・Low）に並べる。各指摘に次を書く。
  - 重要度
  - 観点: 15の観点のうち、該当するもの
  - 場所: ファイルと行など
  - 内容
  - 修正案
- 指摘がないときは、「指摘なし」と書く。
- 外した観点は、「対象外: 観点名（理由）」と書く。
- 3周しても収束しなかった指摘は、「既知の穴」として、指摘と同じ項目で書く。
- 未レビューのときは、その旨と理由だけを書く。収束判定は書かない。
- 末尾に、収束判定を書く。Critical と High の残数と、「終了できる／できない」を示す。品質スコアを使うときは、点数も書く。

表示例（書式の例であり、実際の指摘ではない）:

```text
## レビュー結果

### 指摘
1. 重要度: High
   観点: 完全性
   場所: sample.md 27行目
   内容: 手順3の前提となる手順が書かれていない
   修正案: 手順2に、前提となる操作を足す
2. 重要度: Medium
   観点: 一貫性
   場所: sample.md 8行目
   内容: 変更前の記述が残っている
   修正案: 該当の文を削除する

対象外: 費用対効果（費用が発生しない）
対象外: 利害関係者満足度（利用者が作者本人だけ）

### 収束判定
- Critical: 0、High: 1、Medium: 1
- 品質スコア: 80点（100 - 15 - 5）
- 終了できない（High が残っている）
```
